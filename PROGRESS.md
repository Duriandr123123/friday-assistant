# Состояние проекта

- Модель Android не уточнена; пользователь готов установить APK и проверить.

- Markdown/Obsidian, исходная и исправленная расшифровки, атомарная запись заметок.
- Android Kotlin: foreground запись PCM/WAV, ручная остановка, восстановление WAV, очередь WorkManager, Keystore, прослушивание/просмотр результата, уведомление сохранения.

- Локальная web-панель, README и docs, setup/start/stop, отдельные скрипты автозапуска.
- Debug APK: dist/jarvis-debug.apk. SDK и Gradle: .tools. Gradle Wrapper с проверкой SHA-256.
- Сборка в ASCII-каталоге %LOCALAPPDATA%/JarvisThoughtsBuild обходит ошибку Java tools с кириллицей в пути.
- Whisper small скачан в data/models, CPU int8; после скачивания загрузка модели локальна.

- Wake word, часы/амулет, напоминания и сторонние заметочные сервисы отложены; текущая система личная, не готовый многопользовательский продукт для продажи.
- WebMCP search_notes добавлен с feature detection; в поддерживающем браузере контракт не проверялся. Основная панель не зависит от него. Отдельная браузерная визуальная QA не проводилась.

## Известные ограничения
- Whisper small допускает ошибки имён и терминов; тестовая русская запись имела отдельные ошибки. Нужна проверка на речи пользователя, затем выбор модели/словаря.
- Аудио не удаляется по умолчанию; нет автоматической резервной копии. Удаление приложения удалит его локальные данные.
- При внезапном отключении питания последние несинхронизированные ~1 секунда аудио могут не сохраниться. Гарантии против аппаратного сбоя нет.
- После force-stop Android требуется открыть приложение. Автоостановка по амплитуде экспериментальная.

## Как продолжить
1. Прочитать README и docs/ANDROID.md; пользователь устанавливает dist/jarvis-debug.apk.
2. Для подключения использовать data/connection.txt (содержит секрет, не выводить в логи/чат).
3. После проверки телефона устранить реальные ошибки; не переписывать рабочую структуру.
4. Когда пользователь даст ключ, настроить .env локально, перезапустить и выполнить настоящий AI E2E.

## Диагностика подключения API
- Пользователь включил LLM_PROVIDER=openai; последние ошибки — llm_model_missing.
- В .env OPENAI_API_KEY пуст; отдельно введённая строка не является значением этой переменной. Содержимое не копировать в отчёты.
- Настроена OPENAI_LLM_MODEL=gpt-4.1-mini. В панели добавлены пояснения ошибок настройки и HTTP 401/429.
- Для реального запроса требуется вставить секретный ключ в строку OPENAI_API_KEY=; запросы API при диагностике не выполнялись.
