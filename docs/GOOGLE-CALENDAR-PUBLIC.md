# Общее подключение Google Календаря

Статус: программная поддержка подготовлена, публичное приложение Google ещё не опубликовано и не проверено Google. Действующее личное подключение сохраняется.

## Сценарий покупателя

В панели на компьютере нажать «Подключить Google Календарь», выбрать аккаунт Google и разрешить доступ. Покупатель не должен создавать проект Google Cloud. Для этого официальный установщик должен содержать Desktop OAuth client нашего приложения.

## Подготовка владельцем продукта

1. Указать владельца, рабочий адрес поддержки и принадлежащий ему домен.
2. Разместить на домене описание продукта и политику конфиденциальности; подтвердить владение доменом в Google.
3. Настроить branding и аудиторию общего OAuth-приложения, включить Calendar API, создать клиент Desktop app.
4. Запросить только calendar.events.owned. Подготовить объяснение необходимости доступа и демонстрацию создания и отмены встреч. Пройти требуемую Google проверку перед распространением вне тестовой аудитории.
5. После готовности собрать Windows-пакет с параметром `-GoogleDesktopClient` скрипта `scripts/build-desktop.ps1`, передав оригинальный JSON Desktop client из защищённого локального каталога.
6. Проверить вход отдельного тестового пользователя, обновление токена и повторный запуск приложения. Только затем выпускать установщик с общим клиентом.

Desktop OAuth client распространяется внутри приложения и не является способом сохранить секрет от владельца компьютера. Нельзя использовать для этого Web client. Файл настроек исключён из Git; refresh/access tokens пользователей никогда не включаются в сборку. Общая настройка копируется в каталог данных конкретной установки при первом подключении. Обновление установщика не меняет клиент уже подключённого пользователя.

## Факты для будущей политики конфиденциальности

Это заготовка для проверки владельцем, не опубликованная политика:

- Приложение работает на компьютере пользователя и хранит настройки подключения и токены Google локально.
- Доступ используется для создания встреч по поручению пользователя и отмены событий, созданных приложением. Программа проверяет собственную метку события перед удалением.
- Текущий код не загружает весь календарь для анализа ИИ. Текст голосовых поручений может обрабатываться OpenAI по выбранным пользователем настройкам; это нужно отдельно раскрыть вместе с обработкой аудио.
- Локальные записи, база и экспорт Obsidian сохраняются до удаления пользователем. Нельзя обещать автоматическое удаление этих данных при отзыве Google-доступа.
- Пользователь может отозвать доступ в настройках Google-аккаунта. Контакт поддержки, юридическое имя владельца и адрес сайта должны быть заполнены реальными данными перед публикацией.

Источники: [OAuth для desktop-приложений](https://developers.google.com/identity/protocols/oauth2/native-app), [требования проверки Google](https://support.google.com/cloud/answer/13464321?hl=en).
