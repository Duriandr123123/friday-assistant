# Архитектура

Android/Kotlin → WAV PCM 16 kHz mono → FastAPI → SQLite queue → SpeechToTextProvider → LLMProvider → NotesProvider → Markdown.

## Почему так

- Android AudioRecord пишет PCM сразу в файл. При обычном завершении обновляется WAV-заголовок, при убийстве процесса заголовок восстанавливается по длине файла при следующем запуске приложения. Синхронизация на диск раз в секунду; аппаратный сбой может потерять последний несинхронизированный фрагмент.
- SQLiteOpenHelper хранит очередь на телефоне. WorkManager переживает обычное закрытие приложения и перезагрузку; после принудительной остановки пользователем Android требует снова открыть приложение.
- FastAPI обслуживает REST и встроенную панель без отдельного Node-сервера.
- SQLAlchemy + Alembic дают миграции БД. SQLite WAL и synchronous=FULL; один сервер и один последовательный worker на каталог данных. FileLock запрещает второй процесс на той же базе.
- После STT транскрипт фиксируется отдельно. Сбой AI не теряет его. Результат AI также сохраняется до записи Markdown.
- Markdown записывается через временный файл, fsync и os.replace. Имя с UUID стабильно при правках и повторах.
- FTS5 unicode61 даёт поиск по словам и префиксам, включая кириллицу. Это не семантический поиск и не русская морфология.

## Контракт доставки

Устройство создаёт UUID до записи, сохраняет время с часовым поясом и передаёт тот же UUID при повторах. Сервер принимает только WAV 16 kHz/16 bit/mono до 10 минут и 24 МБ, проверяет заголовок и фактическую длину аудио. SHA-256 возвращается клиенту. Ответ 202 означает, что файл записан на диск и строка БД закоммичена; это ещё не готовая заметка.

Повтор того же UUID и SHA-256 возвращает существующую запись. Другой файл с тем же UUID — 409. Аудио на Android не удаляется после отправки. Между записью файла сервером и фиксацией строки БД может остаться файл без строки; повтор клиента создаст строку снова.

## Состояния

Сервер: queued → processing → saved / awaiting_ai. Ошибка: retry с next_attempt либо failed. Отдельные контрольные точки — raw_transcript и result. После перезапуска processing → queued. Максимум 5 попыток по умолчанию, интервалы 10, 20, 40, 80 секунд; ручной повтор обнуляет счётчик и пересоздаёт AI-результат, но сохраняет расшифровку.

Телефон: recording → queued → uploaded → saved / awaiting_ai. Сетевые ошибки повторяются WorkManager до 8 выполнений с exponential backoff. Ожидание доступной сети само по себе не расходует попытку. После исчерпания — needs_attention и ручной запуск. Ошибки серверной обработки показываются отдельно.

## Смысл и неопределённость

NoteContent запрещает неизвестные поля, задаёт типы/категории, содержит задачи с evidence и deadline_evidence. Проверки отвергают цитаты, которых нет во входном тексте. Системный prompt требует сохранять неопределённость и считать относительные даты от времени записи, а не загрузки. Это снижает риск выдумок, но не доказывает истинность каждого вывода LLM. Пользователь всегда может сверить исходник и аудио.

Сырые и исправленные транскрипты раздельны. Первичный STT-текст неизменяем; PATCH создаёт редакцию пользователя. Если STT ещё не сработал, ручной текст позволяет продолжить обработку, raw_transcript остаётся пустым.

## Провайдеры

- LocalWhisperProvider: faster-whisper, CPU int8 по умолчанию; выбран для простого запуска без ручной установки CUDA.
- CloudSTTProvider: OpenAI transcription API.
- OpenAILLMProvider: Responses API + strict JSON schema, store=false, сетевые таймауты и ограниченные повторы через очередь.
- PendingLLMProvider: дословная заметка со статусом awaiting_ai; не выдаёт себя за AI.
- MockSTTProvider/MockLLMProvider: только тестовый сценарий, результат помечен mock.
- MarkdownNotesProvider: локальная папка, совместимая с Obsidian.

## Безопасность и границы

Bearer-токен обязателен кроме health, статической оболочки панели и описания API. Панель держит токен только в памяти вкладки, рендерит текст через textContent. Android шифрует токен ключом Android Keystore, резервное копирование приложения отключено. Обычный HTTP допустим только в доверенной домашней сети или внутри защищённого VPN; для публичного адреса приложение требует HTTPS. Секреты и транскрипты не пишутся в журнал событий.

Публичное многопользовательское обслуживание не реализовано. Для продажи устройства потребуются отдельные аккаунты, привязка и отзыв устройств, TLS, квоты, резервные копии, политика хранения и обновления безопасности. Микрофон часов/амулета сможет использовать тот же контракт, но само ПО и аппаратная часть устройства не входят в этот MVP.
